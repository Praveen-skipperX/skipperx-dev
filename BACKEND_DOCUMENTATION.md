# Backend Documentation

## Overview

This is a complete OTP-based authentication backend built with Node.js, Express, and MongoDB. The system supports multiple authentication methods including phone SMS, email, and Google OAuth. The backend is designed for production use with proper security, validation, and error handling.

## Technology Stack

- Node.js with ES Modules
- Express.js 4.19.2 - Web framework
- MongoDB with Mongoose 8.3.0 - Database and ODM
- JWT (jsonwebtoken 9.0.2) - Authentication tokens
- Resend 3.2.0 - Email OTP delivery
- MessageCentral - SMS OTP delivery
- Passport.js - Google OAuth authentication
- Express Validator - Request validation
- Express Rate Limit - API rate limiting
- CORS - Cross-origin resource sharing

## Database Schema

### User Model

The User model stores all user information and authentication data.

**Fields:**

- fullname (String, optional) - User's full name
- email (String, unique, sparse) - Email address for email-based auth
- phone (String, unique, sparse) - Phone number with country code for SMS auth
- isVerified (Boolean, default: false) - Whether user has verified their contact
- profileCompleted (Boolean, default: false) - Whether user has completed profile setup
- profile (Object) - Additional profile information
  - currentCourse (String) - Current course name
  - enrolledCourse (String) - Enrolled course name
- createdAt (Date) - Account creation timestamp
- updatedAt (Date) - Last update timestamp

**Indexes:**

- Email: Unique, sparse (allows null values)
- Phone: Unique, sparse (allows null values)

**Notes:**

The sparse indexes allow users to have either email or phone, not necessarily both. This supports flexible authentication methods.

### OTP Model

The OTP model stores one-time passwords for verification.

**Fields:**

- identifier (String, required, indexed) - Email or phone number
- otp (String) - The OTP code (for email) or null (for SMS via MessageCentral)
- verificationId (String) - MessageCentral verification ID for SMS
- expiresAt (Date, required) - OTP expiration timestamp
- createdAt (Date) - OTP creation timestamp

**TTL Index:**

The collection has a TTL (Time To Live) index on expiresAt field that automatically deletes expired OTPs after 5 minutes.

## API Endpoints

### Authentication Endpoints

All authentication endpoints are prefixed with `/api/auth`.

#### 1. Send OTP

**Endpoint:** `POST /api/auth/send-otp`

**Description:** Sends a one-time password to the provided email or phone number.

**Request Body:**

For email:
```json
{
  "email": "user@example.com"
}
```

For phone:
```json
{
  "phone": "9456916070",
  "phoneCode": "+91"
}
```

**Validation:**

- Must provide either email or phone, not both
- Email must be valid format
- Phone must be valid mobile number
- Rate limited to prevent abuse (5 requests per 15 minutes per IP)

**Response (Success):**

```json
{
  "success": true,
  "message": "OTP sent successfully to email",
  "data": {
    "identifier": "user@example.com",
    "expiresAt": "2025-12-25T10:52:00.000Z"
  }
}
```

**Response (Error):**

```json
{
  "success": false,
  "message": "Invalid email format"
}
```

**Implementation Notes:**

- Email OTPs are generated by the backend and sent via Resend
- SMS OTPs are generated by MessageCentral's VerifyNow API
- MessageCentral returns a verificationId which is stored for later verification
- OTPs expire after 5 minutes
- In development mode, email OTP is included in response for testing

#### 2. Resend OTP

**Endpoint:** `POST /api/auth/resend-otp`

**Description:** Resends OTP with 60-second cooldown between requests.

**Request Body:**

Same as send-otp endpoint.

**Cooldown:**

- 60 seconds between resend requests for same identifier
- Returns remaining cooldown time if attempted too soon

**Response (Too Soon):**

```json
{
  "success": false,
  "message": "Please wait 45 seconds before requesting another OTP"
}
```

#### 3. Verify OTP

**Endpoint:** `POST /api/auth/verify-otp`

**Description:** Verifies the OTP and returns JWT token for authentication.

**Request Body:**

For email:
```json
{
  "email": "user@example.com",
  "otp": "1234"
}
```

For phone:
```json
{
  "phone": "+919456916070",
  "otp": "1234"
}
```

**Validation:**

- Must provide either email or phone
- OTP must be provided
- OTP must be 4 digits

**Response (Success):**

```json
{
  "success": true,
  "message": "OTP verified successfully",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": {
      "id": "60f7b3b3b3b3b3b3b3b3b3b3",
      "fullname": "John Doe",
      "email": "user@example.com",
      "phone": "+919456916070",
      "isVerified": true,
      "profileCompleted": true
    },
    "isNewUser": false
  }
}
```

**Implementation:**

- Email OTPs are verified against stored hash in database
- SMS OTPs are verified through MessageCentral's validate API
- Creates new user if first time login
- Returns isNewUser flag to help frontend decide flow
- JWT token expires in 7 days
- Sets isVerified to true on successful verification

#### 4. Get Current User

**Endpoint:** `GET /api/auth/me`

**Description:** Returns current authenticated user's profile.

**Authentication:** Required (JWT token in Authorization header)

**Headers:**

```
Authorization: Bearer <jwt_token>
```

**Response:**

```json
{
  "success": true,
  "message": "User fetched successfully",
  "data": {
    "id": "60f7b3b3b3b3b3b3b3b3b3b3",
    "fullname": "John Doe",
    "email": "user@example.com",
    "phone": "+919456916070",
    "profileCompleted": true,
    "isVerified": true,
    "profile": {
      "currentCourse": "Web Development",
      "enrolledCourse": "Advanced React"
    }
  }
}
```

#### 5. Update Profile

**Endpoint:** `PUT /api/auth/profile`

**Description:** Updates user profile information.

**Authentication:** Required

**Request Body:**

```json
{
  "fullname": "John Doe Updated",
  "email": "newemail@example.com",
  "phone": "+919876543210",
  "profile": {
    "currentCourse": "Data Science",
    "enrolledCourse": "Machine Learning"
  }
}
```

**Validation:**

- Fullname: 2-100 characters
- Email: Valid email format
- Phone: Valid mobile phone format
- All fields are optional
- Cannot update: _id, isVerified, createdAt, updatedAt

**Duplicate Check:**

The system checks if the new email or phone is already used by another user. If so, returns an error.

**Response:**

```json
{
  "success": true,
  "message": "Profile updated successfully",
  "data": {
    "id": "60f7b3b3b3b3b3b3b3b3b3b3",
    "fullname": "John Doe Updated",
    "email": "newemail@example.com",
    "phone": "+919876543210",
    "profileCompleted": true,
    "isVerified": true
  }
}
```

#### 6. Logout

**Endpoint:** `POST /api/auth/logout`

**Description:** Logs out the current user.

**Authentication:** Required

**Implementation:**

Since JWT is stateless, logout is primarily handled client-side by removing the token. This endpoint logs the event for analytics.

**Response:**

```json
{
  "success": true,
  "message": "Logged out successfully",
  "data": null
}
```

#### 7. Google OAuth Login

**Endpoint:** `GET /api/auth/google`

**Description:** Initiates Google OAuth flow.

**Implementation:**

Redirects user to Google login page. After successful authentication, Google redirects back to callback URL.

#### 8. Google OAuth Callback

**Endpoint:** `GET /api/auth/google/callback`

**Description:** Handles Google OAuth callback and returns JWT token.

**Query Parameters:**

Handled automatically by passport-google-oauth20 strategy.

**Success Flow:**

Redirects to frontend with token: `http://localhost:3000/auth/callback?token=<jwt_token>`

**Error Flow:**

Redirects to frontend login with error: `http://localhost:3000/login?error=authentication_failed`

## Services

### Auth Service

Handles user-related database operations.

**Methods:**

- `findOrCreateUser(identifier, isEmail)` - Finds existing user or creates new one
- `generateAuthToken(user)` - Generates JWT token for user
- `getUserById(userId)` - Fetches user by ID
- `updateUserProfile(userId, profileData)` - Updates user profile with validation

### Email Service

Handles email sending via Resend.

**Configuration:**

- API Key: Stored in environment variable RESEND_API_KEY
- From Address: onboarding@resend.dev (or custom domain)

**Methods:**

- `sendOTPEmail(email, otp, expiresAt)` - Sends OTP email with expiration time

**Email Template:**

The OTP email includes:
- 4-digit OTP code
- Expiration time (5 minutes)
- Professional formatting
- Company branding

### SMS Service

Handles SMS sending via MessageCentral VerifyNow API.

**Configuration:**

- Customer ID: C-ABDFD280480048B
- API Key: Stored in MSG_CENTRAL_API_KEY
- Sender ID: SKPRX

**Methods:**

- `sendOTPSMS(phone)` - Sends OTP via MessageCentral, returns verificationId
- `verifyOTPSMS(phone, otp, verificationId)` - Verifies OTP with MessageCentral
- `extractCountryCode(phone)` - Extracts country code from phone number
- `extractMobileNumber(phone)` - Extracts mobile number without country code

**MessageCentral Flow:**

1. Send request to VerifyNow API with phone number
2. MessageCentral generates OTP and sends SMS
3. Returns verificationId to track this OTP request
4. Store verificationId in database
5. When user submits OTP, verify with MessageCentral using verificationId

### OTP Service

Manages OTP generation, storage, and verification.

**Methods:**

- `generateEmailOTP(identifier)` - Generates 4-digit OTP for email
- `storeSMSOTP(identifier, verificationId)` - Stores MessageCentral verification ID
- `verifyEmailOTP(identifier, otp)` - Verifies email OTP
- `verifySMSOTP(identifier, otp)` - Delegates to SMS service for verification
- `hashOTP(otp)` - Hashes OTP for secure storage
- `compareOTP(otp, hashedOTP)` - Compares OTP with stored hash

**Security:**

- Email OTPs are hashed using bcrypt before storage
- SMS OTPs are verified through MessageCentral, not stored in database
- All OTPs expire after 5 minutes
- TTL index automatically removes expired OTPs

## Middlewares

### Authentication Middleware

**File:** `src/middlewares/auth.js`

**Function:** `authenticate`

Validates JWT token and adds userId to request object.

**Usage:**

```javascript
router.get('/protected', authenticate, controller.method);
```

**Behavior:**

- Extracts token from Authorization header
- Verifies token signature and expiration
- Adds userId to req object
- Returns 401 if token is invalid or missing

### Rate Limiting Middleware

**File:** `src/middlewares/rateLimit.js`

**Rate Limits:**

- OTP endpoints: 5 requests per 15 minutes per IP
- Skip rate limit in development mode

**Configuration:**

```javascript
windowMs: 15 * 60 * 1000  // 15 minutes
max: 5                     // 5 requests per window
```

### Validation Middleware

**File:** `src/middlewares/validate.js`

Processes express-validator validation results and returns formatted errors.

**Usage:**

Applied automatically after validation rules in routes.

## Environment Variables

The backend requires the following environment variables in `.env` file:

### General

- `NODE_ENV` - Environment mode (development/production)
- `PORT` - Server port (default: 5000)

### Database

- `MONGODB_URI` - MongoDB connection string (MongoDB Atlas)

### JWT

- `JWT_SECRET` - Secret key for JWT signing (keep secure)
- `JWT_EXPIRES_IN` - Token expiration time (default: 7d)

### Email Service (Resend)

- `RESEND_API_KEY` - API key from Resend dashboard

### SMS Service (MessageCentral)

- `MSG_CENTRAL_CUSTOMER_ID` - Customer ID from MessageCentral
- `MSG_CENTRAL_API_KEY` - API token from MessageCentral
- `MSG_CENTRAL_SENDER_ID` - Sender ID (usually 6 characters)

### Google OAuth

- `GOOGLE_CLIENT_ID` - Google OAuth client ID
- `GOOGLE_CLIENT_SECRET` - Google OAuth client secret
- `GOOGLE_CALLBACK_URL` - OAuth callback URL

### Frontend

- `FRONTEND_URL` - Frontend URL for CORS and redirects

## Security Features

### Input Validation

All user inputs are validated using express-validator:

- Email format validation
- Phone number format validation
- Field length restrictions
- Required field checks

### Rate Limiting

API endpoints are rate-limited to prevent:

- Brute force attacks
- OTP spam
- Resource exhaustion

### JWT Authentication

Secure token-based authentication:

- 7-day token expiration
- Secret key signing
- Token verification on protected routes

### OTP Security

- 4-digit codes for usability
- 5-minute expiration
- Hashed storage for email OTPs
- Verified through third-party for SMS OTPs
- Automatic cleanup of expired OTPs

### Password Hashing

Using bcrypt for OTP hashing:

- 10 salt rounds
- Secure comparison

### CORS Configuration

Configured to allow specific origins only:

- localhost:3000 (development)
- localhost:5173 (Vite development)
- Production domains (skipperx.io, www.skipperx.io)
- Vercel preview deployments

### Protected Fields

Certain user fields cannot be updated via API:

- _id
- isVerified
- createdAt
- updatedAt

## Error Handling

### Error Response Format

All errors follow a consistent format:

```json
{
  "success": false,
  "message": "Error description"
}
```

### HTTP Status Codes

- 200: Success
- 400: Bad Request (validation errors)
- 401: Unauthorized (missing/invalid token)
- 404: Not Found
- 429: Too Many Requests (rate limit exceeded)
- 500: Internal Server Error

### Logging

The backend logs important events:

- Server startup
- Database connection
- OTP send attempts
- Authentication events
- Errors with stack traces

## Development vs Production

### Development Mode

- OTP included in API response
- Mock SMS sending available
- Detailed error messages
- Rate limiting disabled
- CORS allows all origins

### Production Mode

- OTP not included in response
- Real SMS via MessageCentral
- Generic error messages
- Rate limiting enabled
- CORS restricted to specific domains

## Troubleshooting

### MongoDB Connection Issues

- Verify MONGODB_URI is correct
- Check network connectivity
- Ensure IP is whitelisted in MongoDB Atlas
- Verify credentials are correct

### Email Not Sending

- Check RESEND_API_KEY is valid
- Verify email format is correct
- Check Resend dashboard for logs
- In development, check console for OTP

### SMS Not Sending

- Verify MessageCentral credentials
- Check phone number format (must include country code)
- Verify sender ID is approved
- Check MessageCentral dashboard for logs

### JWT Token Issues

- Verify JWT_SECRET is set
- Check token expiration
- Ensure Authorization header format: "Bearer <token>"
- Verify token is not expired

### Rate Limiting

- Wait 15 minutes if limit exceeded
- In development, set NODE_ENV=development to disable
- Check IP address if behind proxy

## Deployment

### Prerequisites

- Node.js 18+ installed
- MongoDB Atlas account and cluster
- Resend account with API key
- MessageCentral account with credentials
- Google Cloud Console project (for OAuth)

### Steps

1. Set up MongoDB Atlas cluster
2. Get connection string and update MONGODB_URI
3. Configure environment variables on hosting platform
4. Deploy backend to hosting service (Railway, Render, Vercel, etc.)
5. Update Google OAuth callback URL to production URL
6. Update CORS allowed origins to include production domains
7. Test all endpoints in production
8. Monitor logs for errors

### Recommended Hosting

- Railway - Easy deployment, built-in MongoDB
- Render - Free tier available, auto-deploys from Git
- Vercel - Serverless functions, fast deployment
- AWS EC2 - Full control, requires more setup
- DigitalOcean - VPS hosting, cost-effective
